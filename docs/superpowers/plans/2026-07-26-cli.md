# `cmd/mamori` CLI (workstream F) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `mamori` CLI: static commands (`explain`, `schema`, `policy`) that read source code, and live commands (`doctor`, `status`) that are thin clients of a running process's admin endpoint, with a Homebrew release to the `xavidop/homebrew-tap` tap.

**Architecture:** A new module `cmd/mamori` whose sole non-stdlib dependency is `golang.org/x/tools/go/packages` (plus the core module `github.com/xavidop/mamori`, reused for the live commands' `Report` type and `Kind` constants; no provider modules, no cloud SDKs). The CLI has two halves that never mix: static commands load Go packages and statically extract `source:` refs (never resolving anything, decision D1), and live commands hit `GET /` on the admin endpoint (workstream B) and render the returned `Report`. Tag and chain parsing shared with `mamorivet` moves into a new standalone stdlib-only module `cmd/mamori/internal/sourcetag` that both `mamorivet` and `cmd/mamori` depend on, so the chain-split and sensitivity heuristics cannot drift between the analyzer and the CLI.

**Tech Stack:** Go 1.26. `golang.org/x/tools/go/packages` for static analysis. Core (`github.com/xavidop/mamori`) for `Report`/`FieldStatus`/`Kind` in the live commands. Standard library for everything else (flag, net/http, crypto/tls, encoding/json). Homebrew release via the existing GoReleaser config.

> **Note (layout changed since this plan was executed):** `tools/sourcetag` and `tools/reconcilevet` no longer exist as separate modules; both were later folded into the `cmd/mamori` CLI module as `cmd/mamori/internal/sourcetag` and `cmd/mamori/internal/vetcheck` (the analyzer is now named `mamorivet`), reachable via `mamori vet ./...` or `go vet -vettool=$(which mamori) ./...`. The `tools/` directory is gone and `go.work` no longer lists either module. See `docs/superpowers/specs/2026-07-18-mamori-design.md` section 11 and `docs/superpowers/specs/2026-07-24-operational-layer-design.md` section 11 for the current design.

## Tag conventions (verified against `decode.go`)

A struct field's config metadata lives in separate struct tags, not inside the source tag:
- `source:"..."` (the ref, or a comma-separated precedence chain).
- `default:"..."` (`Tag.Lookup("default")`; presence matters).
- `optional:"true"` (`Tag.Get("optional") == "true"`).
- `onfail:"..."` (`Tag.Lookup("onfail")`; values keeplast/useDefault/fail).
- `validate:"..."` (validator/v10 syntax: `oneof`, `gte`, `lte`, `required`, `min`, `max`, ...).
- Sensitivity: a field is sensitive if its type is `secret.String`/`secret.Bytes` OR any ref in its chain uses a secret-bearing scheme (the `mamorivet` heuristic, now shared via `cmd/mamori/internal/sourcetag`).

## Admin endpoint contract (verified against `handler.go`)

- `GET /` returns the `Report` as JSON, 200. This is what `doctor`/`status` fetch.
- `GET /healthz` returns `{"status":"ok"|"unhealthy"}` (200/503). Not used by the CLI's report path.
- A process with no `WithAdminHTTP`, or some unrelated service, returns 404 on `/` or a non-`Report` body: that is exit 2 (admin off / not a mamori admin API), distinct from unreachable (exit 3) and auth-failed (exit 4, a 401).
