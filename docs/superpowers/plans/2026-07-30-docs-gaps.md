# Documentation Gaps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add four documentation pages to the mamori docs site, closing gaps between the shipped API surface and what the site documents.

**Architecture:** Four new Astro markdown pages under `site/src/pages/docs/`, four navigation entries in `site/src/layouts/DocsLayout.astro`, and a small number of cross-links from existing pages. Documentation only: no Go source changes, so semantic-release cuts no version.

**Tech Stack:** Astro static site. Pages are plain Markdown with a three-line frontmatter block. The site builds with `npm run build` from `site/`.

**Spec:** [docs/superpowers/specs/2026-07-30-docs-gaps-design.md](../specs/2026-07-30-docs-gaps-design.md)

## Global Constraints

- **Never use the em-dash character (U+2014)** anywhere. Use a spaced hyphen ( - ), a colon, or parentheses. Every task ends with a grep proving none was introduced. This is the constraint most easily violated by prose writing, so check it every time.
- **Accuracy over fluency.** Every option name, default value, type signature, and behavioral claim must be verified against the source in this repo at the time of writing, never recalled from memory. A reference page stating a wrong default is worse than no page, because a reader will trust it and stop checking.
- **No Go source changes.** These tasks touch only `site/` and `docs/`. If a task appears to require a Go change, stop and report it rather than making one.
- **Match house style.** Read the sibling page named in each task before writing. Pages open with an `# H1` matching the frontmatter title, then a short orienting paragraph, then content. Prose is direct and explains reasoning, not just mechanics.
- **Frontmatter shape.** Pages nested two levels deep (`docs/usage/x.md`) use `layout: ../../../layouts/DocsLayout.astro`. Pages at `docs/x.md` use `layout: ../../layouts/DocsLayout.astro`. Getting this wrong breaks the build; verify against a sibling at the same depth.
- **Commit messages use Conventional Commits**, and every commit in this plan is `docs:`, which does not trigger a release.
- **Do NOT run `git commit`.** The repository owner commits. Leave work in the working tree and report the commit message you would have used.

Then `# Watching one ref` as the H1, and these sections in this order. Write the connecting prose yourself in house style; the facts below are non-negotiable and must appear.

**Opening paragraph.** `WatchRef` watches a single ref and returns a raw channel of updates, with no config struct involved. Give the signature verbatim:

```go
func WatchRef(ctx context.Context, p Provider, ref Ref, opts ...Option) <-chan Update
```

**Section "When to use it".** Reach for it when you want one value rather than a configuration struct. Note that the config server itself uses it, which is why it is exported: a caller gets the identical native-watch-or-poll selection the reconciler performs per field, rather than a second independently-maintained copy of the same decision.

**Section "What it does not give you".** This is the page's most important section. State plainly that compared to `Watch[T]` you lose: validation (there is no struct, so no `validate:` tags), the atomic swap and last-good snapshot (you receive raw updates, including error updates, and decide what to do with each), the `PreApply` gate, `Change` diffing and `Changed()`, `Status()` and `Health()`, and history and pinning. A reader who needs any of those wants `Watch[T]`, and should follow a link to [Watching](/docs/usage/watching/).

**Section "Which options apply".** Of the whole `Option` surface, only the clock, poll interval, jitter, and the `WithBackoff` window reach `WatchRef`, because those are the fields the polling adapter reads. The full surface is accepted so a caller needs no second, narrower configuration vocabulary, but options like `WithValidator` and `PreApply` have no effect here. Say that explicitly rather than letting a reader infer it. Link to the options reference at [Options reference](/docs/usage/options/); that page is created in Task 2, and the link is intentionally written now.

**Section "The channel contract".** The returned channel is closed when `ctx` is cancelled. A transient error arrives as an `Update` with a non-nil `Err` and the channel stays open. Channel closure, not an error update, is what signals termination. Include a short, correct Go example showing the receive loop and the `Err` check.

**Section "Native watch versus polling".** A provider implementing `WatchableProvider` is watched natively; if its native watch fails to start, `WatchRef` falls back to polling rather than failing. Every other provider is polled outright.

H1 `# Troubleshooting`. Organize **symptom first**, because a symptom is what the reader actually has. One `##` section per symptom, each naming the likely causes in the order worth checking and the specific diagnostic that confirms each.

Use exactly these five symptoms as the section headings, in this order:

**`## My value is not updating`**
Causes: the field is polled rather than natively watched and the interval has not elapsed (default 30s); the provider has no native watch at all, so it is polled; the value genuinely has not changed, because the poller emits only on change, comparing `Version`, or the raw bytes when `Version` is empty.
Diagnostics: `w.Status()` for per-field age and last-success time; `WithStale(d)` to make staleness visible in `Status` and `Health`; `w.Refresh(ctx)` to force an immediate re-resolve that blocks until the result is applied or rejected. Link to the provider table in the README or [Providers](/docs/providers/) for which schemes watch natively.

**`## My OnChange never fires, or fires once for several changes`**
Causes: debounce coalescing a burst of field changes into a single `Change` event (default 500ms); a handler slow enough that the bounded dispatch queue filled and the oldest event was dropped.
Diagnostics: `WithDebounce(d)` and `WithQueueDepth(n)`; and `Meter.RecordChangeDropped()`, which exists precisely so a dropped event is alertable rather than invisible. Say that a dropped change is silent without a `Meter` installed, because that is the detail that makes this symptom hard to diagnose.

**`## My update was rejected and Get() still returns the old config`**
Open by stating this is the designed behavior, not a bug: an invalid candidate is refused and the last good snapshot keeps serving.
Causes: the candidate failed validation, or a `PreApply` gate rejected it.
Diagnostics: `OnError` receives a `*PreApplyError` in the `PreApply` case, so `errors.As` distinguishes the two; `Meter.RecordApplyRejected(reason)` reports a `RejectReason` that is a closed type with exactly two values, `RejectValidation` and `RejectPreApply`. Link to [Rotation safety](/docs/usage/rotation/).

**`## My process will not start`**
Cause: `Watch` performs a fail-fast initial load, so an unreachable backend at startup fails outright rather than serving a partial configuration. That is deliberate.
Diagnostics: `mamori.Doctor[T](ctx, opts...)` reports every failing ref at once rather than stopping at the first; error kinds separate a terminal cause (`not_found`, `permission_denied`, `unauthenticated`, `invalid`) from a transient one (`unavailable`, `rate_limited`). Mention `optional:"true"` and the `onfail:` tag for fields that legitimately should not block startup. Link to [Doctor](/docs/observability/doctor/) and [Error kinds](/docs/concepts/error-kinds/).

**`## My secret is showing up in logs`**
Causes: the field is a plain `string` or `[]byte` rather than `secret.String` or `secret.Bytes`; or something calls `Reveal()` and passes the result to a logger.
Diagnostics: `mamori vet ./...` flags the first case, and also runs as a `go vet` tool. Link to [vet](/docs/cli/vet/) and [Secret types](/docs/concepts/secret-types/).

Close with a short section pointing at [Getting help](/docs/getting-help/) for anything not covered, and remind the reader to keep real secret values out of any issue they file.
